# Этап 02. Быстрый ввод воды

## Цель этапа

Дать пользователю сверхбыстрый ежедневный сценарий логирования воды без фото и без ручной команды.

## Проблема сейчас

- Вода уже поддерживается доменной моделью, но в UX чата нет удобного быстрого сценария.
- Пользователь не может добавить воду в 1-2 тапа.
- Нет моментального feedback, который возвращает пользователя в привычку логирования.

## UX-spec

### Вход в сценарий

Пользователь нажимает `Добавить воду`.

Бот отправляет короткое сообщение:

```text
Сколько воды добавить?
```

Кнопки:

- `+250 мл`
- `+500 мл`
- `+750 мл`
- `Свой объем`
- `Назад`

### Быстрый сценарий

При нажатии на пресет бот сразу сохраняет запись и отвечает:

```text
+500 мл воды добавлено.
Сегодня: 1.4 / 2.0 л
Осталось до цели: 600 мл.
```

Ниже быстрые действия:

- `Добавить еще`
- `Прогресс`
- `Добавить еду`

### Свой объем

Если пользователь выбирает `Свой объем`, бот просит ввести число в миллилитрах:

```text
Введите объем воды в мл, например: 330
```

Правила:

- принимать только положительное число;
- диапазон должен быть разумным, например от 50 до 3000 мл за одну запись;
- при ошибке бот должен объяснить формат.

### UX обратной связи

После каждого добавления воды пользователь должен видеть:

- сколько добавлено;
- сколько уже выпито сегодня;
- сколько осталось до цели;
- быструю следующую кнопку.

## Требования к UX/UI

- Не просить лишних подтверждений для стандартных объемов.
- После добавления не уводить пользователя в тупик.
- Сценарий должен занимать не более 2 сообщений для пресетов.
- Формулировки должны быть бытовыми, а не медицинскими.

## Задание для разработчика

### Что реализовать

1. Добавить action `Добавить воду` в чате.
2. Добавить inline- или reply-сценарий для пресетов воды.
3. Реализовать ручной ввод объема после `Свой объем`.
4. Использовать существующую доменную поддержку воды через `HealthService.log_water`.
5. После сохранения показывать краткий прогресс по воде за текущий день.
6. Обновить главное меню и переходы назад.

### Вероятные точки изменений

- `src/ai_me/telegram.py`
- `src/ai_me/services/health_service.py` при необходимости только на уровне вспомогательных методов
- `tests/test_telegram.py`
- `tests/test_health_service.py` при необходимости

### Ограничения

- Не делать фото обязательным для воды.
- Не смешивать этот этап с профилем и настройками целей.
- Не использовать slash-команду как основной UX, но можно оставить fallback вроде `/water 500`.

## Критерии приемки

- Пользователь может добавить воду без фото и без ввода команды.
- Стандартные объемы работают за один тап.
- Пользователь может ввести свой объем.
- После сохранения бот показывает понятный прогресс по воде на сегодня.
- Ошибочный ввод объема обрабатывается дружелюбно и без технических ошибок.
- Сценарий не ломает существующую обработку water-only photo.

## Что проверить

### Автотестами

- вход в сценарий `Добавить воду`;
- сохранение каждого пресета;
- ввод собственного объема;
- сообщение об ошибке при невалидном объеме;
- корректный пересчет дневного прогресса;
- возврат в главное меню.

### Вручную

- воду можно добавить за 1-2 тапа;
- пользователь понимает, что произошло после сохранения;
- после ответа бота есть следующий логичный шаг;
- тексты короткие и не перегружают чат.

## Definition of Done

Этап считается завершенным, когда вода становится самым быстрым и понятным ежедневным действием в продукте.
