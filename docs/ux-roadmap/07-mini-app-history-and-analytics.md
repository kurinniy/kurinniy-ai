# Этап 07. Mini App для истории и расширенной аналитики

## Цель этапа

Сделать Mini App местом для просмотра истории, аналитики, графиков и настроек, не перенося туда основной сценарий логирования еды.

## Проблема сейчас

- Mini App read-only и доступен только администратору.
- Обычный пользователь не может использовать его как companion-интерфейс.
- В чате неудобно показывать длинную историю, графики и сравнительную аналитику.

## UX-spec

### Роль Mini App в продукте

Mini App не заменяет чат. Он нужен для:

- истории;
- расширенной аналитики;
- графиков;
- просмотра динамики;
- редактирования настроек и профиля.

### Главные разделы Mini App

- `Сегодня`
- `История`
- `Аналитика`
- `Профиль`

### Раздел "Сегодня"

Показывает:

- калории;
- белок;
- воду;
- шаги;
- список приемов пищи за день.

### Раздел "История"

Показывает:

- список дней;
- приемы пищи внутри дня;
- статус распознаваний;
- переход к редактированию записи.

### Раздел "Аналитика"

Минимальный набор:

- калории по дням;
- белок по дням;
- вода по дням;
- частота логирования;
- streak по дням с логированием.

### Раздел "Профиль"

Показывает и редактирует:

- личные параметры;
- цели;
- напоминания.

## Требования к UX/UI

- Интерфейс должен быть полезен широкой аудитории, а не только админу.
- Числа без контекста не годятся; нужны подписи и сравнения.
- Графики должны быть легкими и читаемыми на мобильном экране Telegram.
- Навигация должна быть понятной без обучения.

## Задание для разработчика

### Что реализовать

1. Снять ограничение Mini App только для администратора, если это соответствует продуктовой политике.
2. Расширить backend payload и API для истории, аналитики и настроек.
3. Переработать frontend Mini App под 4 основных раздела.
4. Добавить графики и агрегаты по ключевым метрикам.
5. Добавить экраны пустых состояний и ошибок.
6. Обновить чат-подсказки, чтобы они вели в Mini App на историю и аналитику.

### Вероятные точки изменений

- `src/ai_me/web/app.py`
- `src/ai_me/web/dashboard.py`
- `src/ai_me/web/auth.py`
- `frontend/src/App.tsx`
- `frontend/src/types.ts`
- `frontend/src/styles.css`
- `tests/test_web_app.py`
- `tests/test_web_dashboard.py`
- `tests/test_web_auth.py`

### Ограничения

- Не переносить в Mini App обязательное логирование еды.
- Если сразу невозможно реализовать полноценные графики, допустим первый релиз с простыми визуализациями и хорошей структурой данных.
- Следить за производительностью Telegram WebApp на мобильных устройствах.

## Критерии приемки

- Обычный пользователь может открыть Mini App.
- В Mini App есть история, аналитика и профиль.
- Интерфейс остается дополнением к чату, а не заменой.
- Пользователь видит не только сырые числа, но и понятную динамику.
- Данные в Mini App совпадают с данными чата.
- Пустые состояния и ошибки оформлены понятно.

## Что проверить

### Автотестами

- авторизацию обычного пользователя в Mini App;
- payload для истории;
- payload для аналитики;
- payload для профиля;
- корректную обработку ошибок auth и пустых данных.

### Вручную

- Mini App открывается внутри Telegram без лишнего трения;
- история читается лучше, чем в чате;
- графики понятны на мобильном экране;
- пользователь понимает, зачем переходить в Mini App;
- чат и Mini App не противоречат друг другу по данным.

## Definition of Done

Этап считается завершенным, когда Mini App становится естественным местом для просмотра и настройки, а чат остается быстрым местом для действий.
