# Этап 03. Редактирование черновика еды до сохранения

## Цель этапа

Снять главный UX-блокер: пользователь должен иметь возможность исправить распознавание до сохранения, а не выбирать только между `Подтвердить` и `Отклонить`.

## Проблема сейчас

- После фото бот показывает черновик и предлагает только `Подтвердить` или `Отклонить`.
- Ошибка распознавания вынуждает пользователя полностью отказаться от записи.
- Нет пользовательского контроля над названием, порцией, временем и составом.

## UX-spec

### После распознавания фото

Вместо текущего бинарного сценария пользователь получает карточку черновика:

```text
Похоже, это курица с рисом.

420 ккал
Б 31 г • Ж 12 г • У 46 г
```

Кнопки:

- `Сохранить`
- `Изменить`
- `Не то блюдо`
- `Отмена`

### Сценарий "Изменить"

После нажатия `Изменить` бот показывает список полей:

- `Название`
- `Порция`
- `Время`
- `Состав`
- `Калории и БЖУ`
- `Назад к черновику`

### Режим редактирования

Для каждого поля бот открывает короткий focused-flow:

- `Название`: просит ввести новое название;
- `Порция`: дает быстрые варианты `Меньше`, `Стандарт`, `Больше` или ручной ввод;
- `Время`: предлагает `Сейчас` или ввод времени в формате `HH:MM`;
- `Состав`: позволяет переписать краткое описание;
- `Калории и БЖУ`: позволяет вручную задать значения.

### Сценарий "Не то блюдо"

Это не полное удаление записи. Это сценарий переписывания черновика:

```text
Введите правильное название блюда или короткое описание.
Например: гречка с куриной грудкой
```

После этого бот пересобирает черновик или хотя бы обновляет название и summary.

### Сохранение

После сохранения бот отвечает:

```text
Сохранено: курица с рисом.

Сегодня:
2 приема пищи
Белок: 54 / 90 г
Вода: 1.2 / 2.0 л
```

Кнопки:

- `Добавить воду`
- `История`
- `Прогресс`

## Требования к UX/UI

- Пользователь должен видеть, что черновик можно исправить.
- Нельзя заставлять пользователя проходить длинную многошаговую форму, если нужно только поправить название.
- Каждый шаг редактирования должен иметь путь назад.
- Тексты должны использовать бытовые слова: `Название`, `Порция`, `Время`, а не внутренние поля модели.

## Задание для разработчика

### Что реализовать

1. Переделать карточку черновика еды и доступные действия.
2. Добавить состояние draft-edit flow в Telegram-боте.
3. Реализовать редактирование полей черновика до подтверждения.
4. Реализовать сценарий `Не то блюдо` как способ переписать распознавание, а не просто отклонить запись.
5. Обновить сохранение черновика так, чтобы сохранялась отредактированная версия.
6. Обновить тесты на callback и текстовые сценарии редактирования.

### Ограничения

- Не делать full-screen форму в Mini App; этап должен работать в чате.
- Если поле нельзя безопасно пересчитать автоматически, разрешить ручное редактирование без повторного ML-анализа.

## Критерии приемки

- После фото пользователь видит кнопку `Изменить`.
- Пользователь может исправить минимум:
  - название;
  - порцию;
  - время;
  - summary/состав.
- Отредактированный черновик действительно сохраняется в итоговую запись.
- Пользователь может отказаться от редактирования и вернуться к черновику.
- Сценарий работает без ввода служебных команд.
- Ошибки ввода времени и чисел обрабатываются понятно.

## Что проверить

### Автотестами

- отображение новых кнопок черновика;
- редактирование названия;
- редактирование порции;
- редактирование времени;
- сценарий `Не то блюдо`;
- сохранение отредактированного черновика;
- отмену редактирования;
- невалидный ввод времени и чисел.

### Вручную

- пользователь может исправить одну ошибку без ощущения, что он проходит анкету;
- после редактирования карточка черновика обновляется;
- итоговое сохранение понятно и дает ощущение полезности;
- при нескольких шагах пользователь не теряется в состоянии бота.

## Definition of Done

Этап считается завершенным, когда пользователь больше не вынужден выбирать между `сохранить ошибку` и `потерять запись`.
