# Этап 03. Редактирование записи еды после распознавания

## Цель этапа

Снять главный UX-блокер: пользователь не должен делать лишний шаг `Сохранить`, если бот и так уверен в распознавании. При этом пользователь должен иметь быстрый путь исправить или отменить запись.

## Проблема сейчас

- После фото пользователь делает лишний шаг `Сохранить`, даже когда распознавание уверенное.
- Ошибка распознавания требует лишнего подтверждения или полного отказа от записи.
- Нет достаточно быстрого post-save сценария `исправить или отменить`.

## UX-spec

### После распознавания фото при высокой уверенности

Если уверенность выше продуктового порога, запись сохраняется сразу, без отдельного нажатия `Сохранить`.

Пользователь получает уже сохранённую карточку:

```text
Сохранено: курица с рисом.

420 ккал
Б 31 г • Ж 12 г • У 46 г
```

Кнопки:

- `Изменить`
- `Отмена`

`Отмена` в этом сценарии означает отмену только что сохранённой записи.

### После распознавания фото при низкой уверенности

Если уверенность ниже продуктового порога или бот не смог нормально определить блюдо, автосохранения нет.

Пользователь получает сообщение вроде:

```text
Я не до конца уверен, что правильно распознал блюдо.
Проверьте запись перед сохранением.
```

Кнопки:

- `Сохранить`
- `Изменить`
- `Отмена`

### Сценарий "Изменить"

После нажатия `Изменить` бот показывает список полей. В high-confidence сценарии это уже сохранённая запись, в low-confidence сценарии — ещё не сохранённый draft.

- `Название`
- `Порция`
- `Время`
- `Состав`
- `Калории и БЖУ`
- `Назад к черновику`

### Режим редактирования

Для каждого поля бот открывает короткий focused-flow:

- `Название`: просит ввести новое название;
- `Порция`: дает быстрые варианты `Меньше`, `Стандарт`, `Больше` или ручной ввод;
- `Время`: предлагает `Сейчас` или ввод времени в формате `HH:MM`;
- `Состав`: позволяет переписать краткое описание;
- `Калории и БЖУ`: позволяет вручную задать значения.

### Сохранение и отмена

После сохранения бот отвечает:

```text
Сохранено: курица с рисом.

Сегодня:
2 приема пищи
Белок: 54 / 90 г
Вода: 1.2 / 2.0 л
```

Кнопки:

- `Добавить воду`
- `История`
- `Прогресс`

Если запись уже была автосохранена, повторного шага сохранения нет.

Если пользователь нажимает `Отмена` сразу после автосохранения, бот удаляет только что созданную запись и подтверждает отмену.

## Требования к UX/UI

- Пользователь не должен делать лишний шаг сохранения, если распознавание достаточно уверенное.
- Пользователь должен видеть, что запись можно быстро исправить или отменить.
- Нельзя заставлять пользователя проходить длинную многошаговую форму, если нужно только поправить название.
- Каждый шаг редактирования должен иметь путь назад.
- Тексты должны использовать бытовые слова: `Название`, `Порция`, `Время`, а не внутренние поля модели.

## Задание для разработчика

### Что реализовать

1. Переделать photo flow так, чтобы при высокой уверенности запись сохранялась сразу.
2. Оставить после автосохранения только действия `Изменить` и `Отмена`.
3. Для низкой уверенности оставить явный шаг `Сохранить`.
4. Реализовать редактирование полей записи и draft через единый UX-сценарий.
5. Обновить отмену так, чтобы она удаляла только что автосохранённую запись.
6. Обновить тесты на callback и текстовые сценарии редактирования.

### Вероятные точки изменений

- `src/ai_me/telegram.py`
- `src/ai_me/services/health_service.py`
- `src/ai_me/storage/*` если потребуется хранить изменяемый черновик
- `src/ai_me/domain/food.py` при необходимости
- `tests/test_telegram.py`
- `tests/test_health_service.py`

### Ограничения

- Не убирать ручное сохранение полностью: оно остаётся fallback-сценарием для низкой уверенности.
- Не делать full-screen форму в Mini App; этап должен работать в чате.
- Если поле нельзя безопасно пересчитать автоматически, разрешить ручное редактирование без повторного ML-анализа.

## Критерии приемки

- При высокой уверенности запись сохраняется без отдельного нажатия `Сохранить`.
- После фото пользователь видит кнопку `Изменить`.
- Пользователь может исправить минимум:
  - название;
  - порцию;
  - время;
  - summary/состав.
- Отредактированная запись действительно сохраняется в итоговую запись.
- Пользователь может отменить автосохранённую запись сразу после фото.
- При низкой уверенности пользователь получает явный сценарий ручного сохранения.
- Сценарий работает без ввода служебных команд.
- Ошибки ввода времени и чисел обрабатываются понятно.

## Что проверить

### Автотестами

- автосохранение при высокой уверенности;
- отображение новых кнопок после автосохранения;
- редактирование названия;
- редактирование порции;
- редактирование времени;
- сохранение при низкой уверенности;
- отмену автосохранённой записи;
- отмену редактирования;
- невалидный ввод времени и чисел.

### Вручную

- пользователь может исправить одну ошибку без ощущения, что он проходит анкету;
- после редактирования карточка записи или черновика обновляется;
- автосохранение выглядит естественно и не пугает пользователя;
- при нескольких шагах пользователь не теряется в состоянии бота.

## Definition of Done

Этап считается завершенным, когда пользователь не делает лишний шаг `Сохранить` при хорошем распознавании, но сохраняет контроль над исправлением и отменой записи.
