# Этап 01. Welcome Flow и основная навигация

## Цель этапа

Сделать так, чтобы пользователь после `/start` сразу понимал:

- зачем ему этот бот;
- какое действие сделать первым;
- как вернуться к основным сценариям без знания команд.

## Что должен закрывать этап

- Первый экран не должен выглядеть как техническая справка.
- Пользователь должен сразу понимать первое полезное действие.
- Основная навигация должна вести к действиям, а не к внутренним сущностям продукта.

## UX-spec

### Основной сценарий для нового пользователя

В текущей реализации первый `/start` открывает отдельный onboarding с иллюстрациями из этапа 09.

После завершения onboarding пользователь попадает на короткий домашний экран:

- одна понятная фраза про первый шаг;
- action-first клавиатура;
- без технических терминов и длинной справки.

Текущий текст домашнего экрана:

```text
Главный экран
Теперь просто отправьте фото еды в чат — я распознаю блюдо и сохраню запись.
```

### Основной сценарий для уже подключенного пользователя

Для уже подключенного пользователя `/start` тоже открывает onboarding, а `/menu` и переходы после `Пропустить` / `Начать` показывают домашний экран.

Домашний экран:

- короткий;
- без технических статусов;
- с явной подсказкой, что можно просто отправить фото;
- с action-first клавиатурой.

Кнопки основного меню:

- `Добавить еду`
- `Добавить воду`
- `История`
- `Прогресс`
- `Профиль`
- `Как это работает`

Дополнительно:

- `Помощь`

### Сценарий "Как это работает"

После нажатия на `Как это работает` бот отправляет короткое объяснение:

1. отправь фото еды;
2. бот распознает блюдо и сохранит запись;
3. запись можно удалить или отредактировать;
4. цели настраиваются в профиле;
5. отчеты можно включить отдельно.

Текст должен быть коротким и без перечисления технических команд.

### Сценарий ошибок

- если пользователь не зарегистрирован и пытается перейти в сценарий через кнопку, бот сначала завершает подключение или просит `/start`;
- если текущий action пока не реализован, бот не должен отвечать "неизвестная команда", а должен дать понятный ответ вида `Этот раздел скоро появится. Пока можно отправить фото еды или открыть /help`.

## Требования к UX/UI

- Приветственный экран должен помещаться в одно сообщение без простыни текста.
- На первом экране не должно быть технических терминов вроде `draft_id`, `digest`, `context_date`.
- Меню должно вести к действиям, а не к внутренним сущностям системы.
- Бот должен постоянно напоминать, что еду можно отправить просто фотографией.

## Задание для разработчика

### Что реализовать

1. Переделать `/start` и стартовые сценарии так, чтобы первый экран был понятным consumer entry point, а не технической справкой.
2. Сделать домашний экран доступным после onboarding и по `/menu`.
3. Обновить reply keyboard на action-first набор кнопок.
4. Добавить обработку текстовых кнопок:
   - `Добавить еду`
   - `Добавить воду`
   - `История`
   - `Прогресс`
   - `Профиль`
   - `Как это работает`
5. Обновить `/help`, чтобы он оставался fallback-справкой, но не был главным первым экраном.
6. Сохранить обратную совместимость со slash-командами.

### Вероятные точки изменений

- `src/ai_me/telegram.py`
- `tests/test_telegram.py`

### Ограничения

- Не удалять текущие команды.
- Не вносить в этом этапе изменения в хранилище данных, если можно обойтись без них.
- Не смешивать welcome-flow с настройками профиля; профиль будет отдельным этапом.

## Критерии приемки

- Новый пользователь после `/start` получает понятный первый экран, а не технический список команд.
- Уже существующий пользователь после `/menu` получает домашний экран с action-first кнопками.
- `/start` не возвращает пользователя в старую техническую справку.
- В reply keyboard присутствуют основные пользовательские действия, а не только служебные разделы.
- Кнопка `Как это работает` выдает краткий понятный onboarding.
- Пользователь может понять первый шаг без чтения `/help`.
- Старые slash-команды продолжают работать.

## Что проверить

### Автотестами

- `/start` для нового пользователя.
- `/start` для существующего пользователя.
- `/menu` для существующего пользователя.
- состав reply keyboard для обычного пользователя;
- состав reply keyboard для администратора;
- обработку `Как это работает`.

### Вручную

- новый пользователь видит ясный CTA;
- существующий пользователь не получает перегруженный экран;
- в интерфейсе нет терминов, непонятных массовой аудитории;
- пользователь может с первого экрана перейти к еде или воде за один тап.

## Definition of Done

Этап считается завершенным, когда первый экран перестает быть технической справкой и становится понятным consumer entry point в продукт.
