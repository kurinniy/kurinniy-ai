# Этап 05. Mini App: архив истории и карточки записей

## Цель этапа

Сделать Mini App основным местом для просмотра архива приемов пищи и распознаваний, не перенося туда обязательное логирование еды.

## Проблема сейчас

- В чате неудобно показывать длинную историю по дням.
- Пользователю нужен экран, где можно спокойно открыть карточку записи или распознавания.
- Telegram должен оставаться местом для быстрых действий, а не тяжелой навигации по архиву.

## UX-spec

### Роль Mini App на этом этапе

Mini App выступает как companion-интерфейс для:

- просмотра истории приемов пищи;
- просмотра истории распознаваний;
- открытия карточки записи;
- открытия карточки распознавания.

Полное редактирование и удаление внутри Mini App можно отложить на следующий этап.

### Основные разделы Mini App

В текущей реализации архив уже встроен в более широкую структуру Mini App:

- `Сегодня`
- `История`
- `Аналитика`
- `Профиль`

На этом этапе архивная часть живет внутри вкладки `История`.

### Раздел `Сегодня`

Показывает:

- калории;
- белок;
- воду;
- число приемов пищи;
- список приемов пищи за выбранный день.

### Раздел `История`

Показывает:

- список дней;
- приемы пищи внутри дня;
- компактные карточки элементов;
- переход к карточке конкретной записи.
- отдельный блок `Распознавания` с последними черновиками и их статусами.

Если история пустая, пользователь видит понятное пустое состояние:

```text
Пока нет сохраненных приемов пищи. Отправьте первое фото еды в чат.
```

### Карточка записи

Карточка сохраненной записи должна содержать:

- название;
- время;
- калории и БЖУ;
- краткий summary/состав, если он есть;
- фото, если оно доступно.

Если фото временно недоступно, карточка все равно должна открываться без падения.

### Блок `Распознавания`

В текущем приложении распознавания не вынесены в отдельную верхнюю вкладку. Вместо этого они показываются отдельным блоком внутри экрана `История`.

Блок показывает:

- последние распознавания;
- статусы:
  - `Ожидает решения`
  - `Сохранено`
  - `Отклонено`
- краткое описание;
- время;
- калории;
- переход к карточке распознавания.

### Карточка распознавания

Карточка должна содержать:

- название;
- summary;
- статус;
- confidence;
- калории и БЖУ;
- фото, если оно доступно.

### Ограничение этапа

Карточки записи и распознавания на этом этапе остаются read-only: пользователь может спокойно открыть архивную карточку, но полное редактирование и удаление уже сохранённых записей не являются обязательной частью данного шага.

## Требования к UX/UI

- Mini App должен быть доступен обычному пользователю, а не только админу.
- Интерфейс должен быть лучше для чтения архива, чем чат.
- Пустые состояния должны быть человечными.
- Отсутствие фото не должно ломать карточки.
- Чат должен вести пользователя в Mini App, а не дублировать тяжелую историю.

## Задание для разработчика

### Что реализовать

1. Открыть Mini App для обычных пользователей.
2. Добавить frontend-навигацию с отдельным экраном `История`, в котором доступны и архив приемов пищи, и распознавания.
3. Расширить backend payload для:
   - истории приемов пищи;
   - истории распознаваний;
   - detail карточки записи;
   - detail карточки распознавания.
4. Реализовать экран истории по дням.
5. Реализовать карточки записи и распознавания.
6. Сделать устойчивый fallback, если фото временно недоступно.
7. Обновить чатовые тексты так, чтобы они вели пользователя в Mini App для полной истории.

- `tests/test_web_app.py`
- `tests/test_web_dashboard.py`

### Ограничения

- Не переносить в Mini App обязательное логирование еды.
- Не делать на этом этапе полноценное редактирование сохраненных записей.
- Не требовать фото для открытия карточки, если media временно недоступна.

## Критерии приемки

- Обычный пользователь может открыть Mini App.
- В Mini App есть экран `История`, где доступны и архив приемов пищи, и блок распознаваний.
- Пользователь может просматривать архив приемов пищи по дням.
- Пользователь может открыть карточку сохраненной записи.
- Пользователь может открыть карточку распознавания.
- Статусы распознаваний показаны понятным человеческим языком.
- Пустые состояния оформлены понятно.
- Отсутствие фото не ломает карточки и не вызывает 500.

## Что проверить

### Автотестами

- авторизацию обычного пользователя в Mini App;
- payload для истории;
- payload для распознаваний;
- payload detail карточки записи;
- payload detail карточки распознавания;
- открытие карточек без доступного фото.

### Вручную

- Mini App открывается у обычного пользователя без лишнего трения;
- история читается лучше, чем в чате;
- карточки записи и распознавания открываются стабильно;
- пустые состояния выглядят понятно;
- пользователь понимает, что архив живет в приложении, а быстрые действия — в чате.

## Definition of Done

Этап считается завершенным, когда Mini App становится понятным архивом истории и распознаваний, а чат остается местом для быстрых действий и recovery.
