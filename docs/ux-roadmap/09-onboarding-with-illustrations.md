# Этап 09. Новый онбординг с иллюстрациями

## Цель этапа

Добавить короткий пошаговый онбординг, который за 3 экрана объясняет пользователю:

- что это за бот;
- какую пользу он дает каждый день;
- где смотреть историю и профиль.

Онбординг должен снижать тревогу перед первым действием и увеличивать вероятность, что пользователь сразу отправит первое фото еды.

## Проблема сейчас

- После запуска пользователь не получает понятного знакомства с продуктом.
- Нет визуального объяснения, как работает бот и зачем возвращаться в него каждый день.
- Пользователь не узнает заранее, что часть сценариев доступна в Mini App.

## UX-spec

### Общий формат

Онбординг показывается как пошаговый мастер из `3` экранов.

На каждом экране есть:

- иллюстрация;
- заголовок;
- основной текст;
- индикатор шага;
- кнопки управления.

Кнопки:

- `Далее`
- `Пропустить`

На последнем шаге:

- `Начать`

### Когда показывать онбординг

Показывать онбординг по команде `/start` всем пользователям до перехода в основной домашний экран.

Если пользователь уже проходил онбординг раньше, `/start` всё равно открывает его заново как короткое повторное знакомство с продуктом.

Если пользователь нажимает `Пропустить` или `Начать`, бот сразу переводит его в основной домашний экран.

### Тональность

- простая;
- спокойная;
- дружелюбная;
- без внутренних технических терминов;
- без перегрузки цифрами и инструкциями.

## Поведение после завершения

После нажатия `Начать` пользователь попадает в основной сценарий бота:

- домашний экран;
или
- первый CTA с действиями `Добавить еду`, `Добавить воду`, `Открыть`.

Важно: окончание онбординга должно вести к действию, а не к тупику.

## Требования к UX/UI

- Каждый шаг должен помещаться на один мобильный экран без ощущения перегруза.
- Текст должен быть коротким: 1 заголовок и 2 коротких абзаца максимум.
- Иллюстрация должна быть главным акцентом экрана.
- Пользователь всегда должен видеть, что он может пропустить онбординг.
- На последнем шаге CTA должен быть более явным, чем на предыдущих.
- Визуальный стиль онбординга должен совпадать с тоном продукта: спокойный, современный, не кричащий.

## Задание для разработчика

### Что реализовать

1. Добавить отдельный onboarding flow из 3 шагов.
2. Показывать onboarding по команде `/start` перед переходом в основной интерфейс.
3. Реализовать навигацию по шагам:
   - `Далее`
   - `Пропустить`
   - `Начать` на последнем шаге
4. Поддержать отображение:
   - заголовка;
   - текста;
   - иллюстрации;
   - индикатора шага.
5. Подключить изображения для каждого шага, когда финальные файлы будут переданы.
6. После завершения онбординга переводить пользователя в основной стартовый сценарий, а не просто закрывать flow.
7. Обеспечить, чтобы после `Пропустить` или `Начать` пользователь попадал в основной интерфейс без лишних промежуточных сообщений.

### Что не делать в этом этапе

- Не смешивать онбординг с настройкой профиля.
- Не превращать онбординг в длинную инструкцию по всем функциям продукта.
- Не перегружать шаги дополнительными кнопками и ветвлениями.
- Не вставлять технические термины вроде `draft`, `callback`, `digest payload`.

### Вероятные точки изменений

- `src/ai_me/telegram.py`
- `src/ai_me/services/health_service.py` или связанный user state слой, если нужно сохранять статус прохождения онбординга
- `src/ai_me/storage/base.py`
- `src/ai_me/storage/memory.py`
- `src/ai_me/storage/mysql.py`
- `src/ai_me/domain/user.py` при необходимости
- `tests/test_telegram.py`
- `tests/test_health_service.py`
- `tests/test_mysql_store.py`

## Критерии приемки

- Новый пользователь после первого `/start` видит пошаговый онбординг из 3 экранов.
- На каждом шаге есть иллюстрация, заголовок, текст и понятные кнопки навигации.
- Тексты шагов соответствуют утвержденной редактуре этого документа.
- Пользователь может пропустить онбординг в любой момент.
- После завершения онбординга пользователь попадает в понятный основной сценарий бота.
- Онбординг не повторяется бесконечно при каждом `/start`.
- После передачи изображений они корректно подключаются в каждый шаг.

## Что проверить

### Автотестами

- показ онбординга новому пользователю;
- переход между шагами;
- `Пропустить`;
- `Начать` на последнем шаге;
- неповторный показ после завершения;
- неповторный показ после пропуска;
- переход в основной экран после онбординга.

### Вручную

- шаги читаются быстро и без перегруза;
- иллюстрация визуально доминирует над текстом;
- пользователь понимает продукт уже после первого экрана;
- второй экран повышает интерес к ежедневному использованию;
- третий экран объясняет роль Mini App без ощущения, что пользователя уводят из основного сценария;
- после `Начать` пользователь не теряется и видит следующий полезный шаг.

## Definition of Done

Этап считается завершенным, когда новый пользователь за 3 коротких экрана понимает, что это за бот, зачем возвращаться каждый день и где искать историю и профиль.
